# Running BDD Suites in CI

A playwright-bdd CI pipeline has two mandatory phases: **code generation** (`bddgen`) and **test execution** (`playwright test`). You cannot run `playwright test` alone — the `.spec.ts` files it needs are generated by `bddgen` from your `.feature` files.

## The Two-Phase Pipeline

```bash
# Phase 1: Generate .spec.ts files from .feature files
npx bddgen

# Phase 2: Execute the generated tests
npx playwright test
```

These must run in sequence in the same CI job (or the generated files must be passed as artifacts between jobs).

A custom config path must be provided to **both** commands:

```bash
npx bddgen -c playwright.config.ts && npx playwright test -c playwright.config.ts
```

## Parallel Execution with Sharding

For large suites, distribute across multiple CI runners using Playwright's `--shard` flag. Sharding splits the scenario set by index without requiring tag coordination.

```bash
# Runner 1 of 4
npx bddgen && npx playwright test --shard=1/4

# Runner 2 of 4
npx bddgen && npx playwright test --shard=2/4
```

`bddgen` must run on each shard before the test command — it is fast (< 5 seconds for most suites) and does not require network access.

## Retry Configuration

Configure retries globally for CI runs. Retries are disabled locally by default to preserve isolation visibility:

```typescript
// playwright.config.ts
import { defineConfig } from '@playwright/test';
import { defineBddConfig } from 'playwright-bdd';

const testDir = defineBddConfig({
  features: 'features/**/*.feature',
  steps: 'steps/**/*.steps.ts',
});

export default defineConfig({
  testDir,
  retries: process.env.CI ? 2 : 0,
  reporter: [
    ['html', { open: 'never' }],
    ['json', { outputFile: 'test-results/results.json' }],
  ],
  use: {
    video: 'on-first-retry',
    screenshot: 'only-on-failure',
    trace: 'on-first-retry',
  },
});
```

## Duration Budgeting

Set a timeout budget per suite tier to prevent runaway tests from blocking the pipeline:

```typescript
export default defineConfig({
  timeout: 30_000,        // 30s per scenario
  expect: { timeout: 5_000 }, // 5s per assertion
  globalTimeout: 10 * 60 * 1000, // 10-minute hard stop for full suite
});
```

Tag slow scenarios with `@slow` and give them an extended timeout via playwright-bdd's special tag:

```gherkin
@slow
@timeout:60000
Scenario: Full order lifecycle including email delivery confirmation
  Given I am a registered customer
  When I place an order for "Wireless Keyboard"
  Then I receive an order confirmation email within 30 seconds
```

## Full GitHub Actions Workflow

This is a working example with `bddgen`, sharding, retries, and artifact upload:

```yaml
name: BDD Suite

on:
  push:
    branches: [main]
  pull_request:

jobs:
  bdd:
    name: BDD (${{ matrix.shard }}/${{ strategy.job-total }})
    runs-on: ubuntu-latest
    strategy:
      fail-fast: false
      matrix:
        shard: [1, 2, 3, 4]

    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Install Playwright browsers
        run: npx playwright install --with-deps chromium

      - name: Generate BDD test files
        run: npx bddgen

      - name: Run BDD suite (shard ${{ matrix.shard }}/4)
        run: npx playwright test --shard=${{ matrix.shard }}/4
        env:
          CI: 'true'
          API_BASE_URL: ${{ secrets.STAGING_API_URL }}

      - name: Upload test results
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: playwright-report-shard-${{ matrix.shard }}
          path: playwright-report/
          retention-days: 14

      - name: Upload test traces on failure
        if: failure()
        uses: actions/upload-artifact@v4
        with:
          name: playwright-traces-shard-${{ matrix.shard }}
          path: test-results/
          retention-days: 7

  merge-reports:
    name: Merge Reports
    needs: bdd
    runs-on: ubuntu-latest
    if: always()
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
      - run: npm ci

      - name: Download all shard reports
        uses: actions/download-artifact@v4
        with:
          pattern: playwright-report-shard-*
          merge-multiple: true
          path: all-reports/

      - name: Merge Playwright reports
        run: npx playwright merge-reports --reporter html all-reports/

      - name: Upload merged report
        uses: actions/upload-artifact@v4
        with:
          name: bdd-report-merged
          path: playwright-report/
          retention-days: 30
```

!!! tip "bddgen is fast — run it on every shard"
    Do not try to pass generated `.spec.ts` files between shards as artifacts. `bddgen` typically completes in 2-5 seconds, making per-shard regeneration the simpler and more reliable approach.

## Tag-Based Test Filtering

Use tag filtering in `bddgen` to run only the scenarios relevant to a PR or pipeline stage:

```bash
# Run only smoke scenarios
npx bddgen --tags "@smoke" && npx playwright test

# Run everything except quarantined
npx bddgen --tags "not @quarantine" && npx playwright test

# Run only API scenarios (no browser required)
npx bddgen --tags "@api" && npx playwright test
```
